- Seller availability (not blocked/paused/10-day inactive) is enforced server-side via SQL `seller_is_available()` in checkout, finalize and offers; clients use `isSellerInactive` from fetchSellerProfiles only - why: per-screen copies drifted and let unavailable sellers through.
- Use `onAppResume()` (src/lib/appResume.ts) for "user returned to app" logic - why: web focus/visibility events don't fire reliably in the native iOS WebView.
- Nav badge realtime/listeners and the app icon badge live in `useNavBadgesSync()`, mounted once at the App root - why: BottomNav-only mounting left the icon badge stale on other screens.
- Feed RPCs that filter on other users' profile fields must be SECURITY DEFINER - why: profile RLS returns NULLs to callers, letting inactive/paused sellers through LEFT JOIN filters.
- Checkout quotes are service-only snapshots, and settlement uses claim_checkout plus atomic settle_checkout_orders - why: payment-time prices stay binding and order creation cannot race orphan refunds.
- Seller holds use _shared/heldFunds.ts in status, dashboard and payout - why: unresolved claims and bank disputes must produce the same withdrawable balance everywhere.
- Return carrier delivery requires admin_verify_return before automated refund retries - why: a delivery scan alone cannot prove parcel contents or recipient.
- User blocks are directional private records enforced symmetrically in discovery and new transactions; existing orders remain accessible - why: blocking must protect users without preventing fulfillment or dispute resolution.
- User-authored comments and order messages have database write-validation triggers - why: direct client writes and service endpoints must not bypass scam-payment restrictions.
- Public seller activity uses seller_profiles availability markers, never precise timestamps or base-profile fallback - why: privacy must not weaken the shared inactivity rule.
- Keep profiles_public readable for installed clients with day-rounded dates; seller_profiles derives coarse availability from private profiles - why: revoking legacy reads breaks released apps, while rounded dates must not shift the current 10-day cutoff.
- Payment webhooks use leased event claims and unique notification delivery keys - why: concurrent retries must not duplicate alerts and failed work must remain retryable.
- Marking orders shipped requires a recent service-written carrier validation permit - why: direct client calls must not bypass carrier evidence and tracking reuse checks.
- Frontend toast messages go through src/lib/toast and shared userMessage presentation - why: punctuation and provider wording must be consistent without modifying stored diagnostics.
- Admin CSV exports use the shared csv encoder for every cell - why: quoting alone does not neutralize user-supplied spreadsheet formulas.
- Welcome alerts and client error attribution use verified login identity; internal tools use matchesServiceCredential or requireAdmin - why: decoded JWT claims are attacker-controlled without verification.
- Push registration never deletes subscriptions belonging to another user; account switching relies on sign-out cleanup - why: knowing an endpoint does not prove device ownership.
- Pre-signup eligibility responses never include debt amounts or account-linked reasons - why: signup needs a generic eligibility decision, not private financial details.
